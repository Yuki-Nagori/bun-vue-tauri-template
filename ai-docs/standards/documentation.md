# 文档规范

更新日期：2026-10-04。均为项目约定。

## 结构与信息归属

分层与职责见[规范索引](README.md)：架构说明目标与边界，规范记录长期规则，task 保存范围与证据，索引保存状态摘要。目录入口用 `README.md`；task 是 `task/NNN-name.md`，不为单个文本建子目录；重要模块积累到需要专题说明时再建 `modules/`，不预建空目录。

入口保持简短，细节下沉到主题文件；同一张版本表或同一条规则只在一处维护，其他位置链接过去，移动文件时更新全部引用。

## 写作与格式

- UTF-8；段落表达完整含义，列表用于真正并列或顺序的内容，表格用于比较和映射，不把长段落塞进单元格。
- 代码块标语言；路径、命令、类型用行内代码；文档间链接用相对路径，不出现个人机器的绝对路径。
- 链接文字说明目标内容，不写「点这里」；不写容易过期的计数（「三个文件」「下一空闲编号」）。
- 「已实现」「规划」「候选」「待验证」分开表述；规划能力不写成已有能力，任务完成不自动等于产品能力完成。

## 图表

目录树、分层关系用纯文本代码块；流程 / 时序确需图形时用 mermaid，入库前经渲染校验（如 mermaid.ink 返回 200）。当前文档体系全部使用文本图。

## 同步

改技术行为的 commit 同步受影响的架构与规范篇；task 遵循[提交规范](commits.md)更新工作记录。文档-only 改动检查本地链接、路由覆盖与旧路径残留。删除功能时同步清理失效说明与示例，历史原因写进 task，不保留一份看似可用的旧文档。
